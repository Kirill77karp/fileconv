# ADR-001: Выбор языка программирования и фреймворка

- **Статус:** Accepted
- **Дата:** 2026-01-15
- **Автор:** Иванов И.И.

## Контекст

Проект — REST API для конвертации файлов. Команда из 3 человек
владеет Python и JavaScript. Срок MVP — 8 недель. Требуется
автогенерация OpenAPI-спецификации и поддержка async I/O для
параллельных запросов на конвертацию.

## Рассмотренные альтернативы

1. **Python + FastAPI** — быстрый старт, нативная поддержка async, автодок.
2. **Node.js + Express** — знакомый стек, но хуже с CPU-bound (Pillow, pandas).
3. **Go + Gin** — быстрее на нагрузках, но дольше писать MVP и меньше
   готовых библиотек для конвертации.

## Решение

**Python 3.11 + FastAPI.**

## Обоснование

- Команда уже знает Python — нулевой ramp-up.
- FastAPI генерирует OpenAPI из коробки (требование задания — docs/api/openapi.yaml).
- Pydantic 2 валидирует вход и сериализует выход без ручного кода.
- Богатая экосистема для конвертации: Pillow, python-docx, pandas, openpyxl.
- Async I/O + Celery решают CPU-bound задачи через отдельные воркеры.

## Последствия

**Плюсы:**
- Быстрая разработка MVP.
- Автодокументация Swagger UI / ReDoc.
- Огромное сообщество и примеры.

**Минусы:**
- GIL ограничивает параллелизм — выносим в Celery.
- Уступает Go по throughput на экстремальных нагрузках.
