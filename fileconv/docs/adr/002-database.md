# ADR-002: Выбор базы данных

- **Статус:** Accepted
- **Дата:** 2026-01-16
- **Автор:** Петров П.П.

## Контекст

Нужно хранить пользователей, задачи конвертации и метаданные файлов.
Ожидаемая нагрузка MVP — до 200 DAU, до 5 000 задач в сутки. Требуется
надёжность, поддержка JSONB для гибких метаданных и полнотекстовый поиск
по истории (FR-004).

## Рассмотренные альтернативы

1. **PostgreSQL** — ACID, JSONB, полнотекстовый поиск, async-драйвер asyncpg.
2. **MySQL** — популярен, но слабее JSON и FTS.
3. **MongoDB** — гибкая схема, но избыточна для реляционной модели задач.
4. **SQLite** — только для тестов, не тянет конкурентную запись.
5. **Redis** — не подходит как основное хранилище.

## Решение

**PostgreSQL 16** + SQLAlchemy 2.0 async + asyncpg.

## Обоснование

- Реляционная модель (User 1—N Task) идеально ложится на Postgres.
- JSONB пригодится для хранения метаданных конвертации (EXIF, размеры, хэши).
- Встроенный полнотекстовый поиск — без Elasticsearch на MVP.
- asyncpg — самый быстрый async-драйвер под Python.
- Легко масштабируется репликацией и партиционированием по created_at.

## Последствия

**Плюсы:**
- Надёжность и предсказуемость.
- Богатая экосистема инструментов (pgAdmin, pg_dump).
- Async из коробки.

**Минусы:**
- Нужен отдельный сервис в docker-compose.
- Схема требует миграций (Alembic) при росте.
