# ADR-004: Модель ветвления

- **Статус:** Accepted
- **Дата:** 2026-01-18
- **Автор:** Иванов И.И.

## Контекст

Команда из 3 человек, 8 недель, MVP. Нужна модель ветвления,
которая не тормозит разработку и позволяет выпускать релизы
каждую неделю.

## Рассмотренные альтернативы

1. **Git Flow** — main + develop + release + hotfix. Избыточен для 3 человек.
2. **GitHub Flow** — main + feature/*. Прост, быстр, CI-friendly.
3. **Trunk-based** — все в main с короткоживущими ветками. Требует зрелого CI.

## Решение

**GitHub Flow.**

- `main` — всегда стабильная, готовая к деплою.
- `feature/*` — ветки под фичи, живут ≤ 3 дней.
- `release/*` — для подготовки релиза (1 на версию).
- `hotfix/*` — срочные фиксы в прод.

## Обоснование

- Команда маленькая — Git Flow создаст лишнюю бюрократию.
- Trunk-based требует feature flags, которых у нас нет.
- GitHub Flow оптимален: PR → review → merge → CI → deploy.

## Последствия

**Плюсы:**
- Быстрые релизы (каждую неделю).
- Понятная история — main всегда зелёный.
- Легко делать hotfix.

**Минусы:**
- Нет отдельной ветки develop — неудобно для параллельных крупных фич.
- Требует дисциплины в PR-ревью.
